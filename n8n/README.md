The three summary node files are built from shared parts (`_summary_input.js`, `_summary_checker.js`,
`*_tail.js`) by `python3 tools/build_n8n_code.py`; edit the parts, rebuild, then paste.

The variable rules live in the n8n data table `template_variables`
(id oEGx7TvhjZ2X6HeB). `variables/` at the repo root is its seed.

Flow: Gmail → Config → Brief Organizer → Client Profiler → Read template
variables → Template rules → researchers (rules injected) → Assemble market → Prepare context →
Context Writer → Check context (template 1.4) → Architect input → Phase
Architect → Chain check → Route → Workstream agent → Chain check → Route → Deliverable agent → Chain check → Route →
Governance agent → Chain check → Route [each agent once back with its violations] → Assemble drafts →
Copywriter (one call, whole deck) → Check copy → [Copywriter retry → Check
retry] → Prepare summary → Summary Writer → Check summary → Summary OK? →
[Summary Writer retry → Check summary] → Final summary → Build render payload → Build deck (Render) → reply.

Tests: `node n8n/tests/harness.js` runs these files with mocked n8n lookups.
Test entry point: the "Test brief (no email)" webhook, which only runs with the
X-JML-Test header secret. Its message ids start with `test-`; "Real email?"
stops those runs after Name attachment, so no email is sent and a good run ends
as success. (The no-deck and missing-info replies still fail on test runs.)

Model settings: researchers and copywriter use claude-sonnet-5-5 with a 16,384
output cap. The copywriter runs adaptive thinking at low effort: with the model
default it spent the whole cap thinking and returned nothing (execution 25).

Failure handling: Client Profiler, Offering researcher and Topic researcher
continue on error. A failed profile leaves problem_focus empty, both IFs take
their stubs, and the deck is built without market research (checkProfiler logs
`profiler_failed`). Copywriter, Phase Architect and Summary Writer already
continued on error with code fallbacks.

Phase Architect model: claude-sonnet-5-5, output cap 32,000 with streaming on
(the Anthropic SDK refuses non-streaming calls above ~21k tokens). Long
engagements need it: a 40-week plan with 10 workstreams retried once and used
the room (execution 555). Streaming hides the token count in the run log.
Plan size limits (prompt + validator): up to 12 workstreams and 16 deliverables;
the schema tolerates 16 workstreams so an oversized plan reaches the validator
and gets a retry instead of a parser error. When the partner's email names or
counts the workstreams, the Brief Organizer records them in
`soft_fields.workstreams` (`value`, `count`) and the Phase Architect plans
exactly those streams at any length, with any number per phase; a stream that
runs in several phases repeats its name in each, and fewer phases are planned
when streams times phases would pass 12 (Oct 18). Without stated streams the
default stays 2 to 4 per phase, more than 8 only past 16 weeks. Phases of 16
weeks or more may add check-ins so no 6-week gap is left; before Oct 18 a phase
of 20 weeks or more could never pass the checker.
Tests: `node phase_architect/tests/plan_size_test.js` (84 rule-following plans,
2 to 52 weeks, 1 to 12 workstreams) and `python3 tests/workplan_render_size.py`
(renders each and checks the layout).

## Four-agent Phase Architect chain (Oct 21, 2026)

The single Phase Architect call and its Validate plan / Plan valid? loop are replaced by four agents and one router:

- **Phase Architect** (the lead): sub-questions, phases, gates, and each phase's length sized from the work it holds
  (`sizing`: drivers with their evidence, pieces of work from the method library's `sizing_units`). Architect input
  now passes `method_library` with `sizing_units` and `sizing_common`. Model: Sonnet 5.5, 32k cap, streaming.
- **Workstream agent**, **Deliverable agent** (with a `format` per deliverable: presentation, report, model, dashboard,
  playbook, training, working solution), **Governance agent**. Sonnet 5.5, 20k cap, adaptive thinking at medium effort.
- **Chain check** (code) runs after every agent: it reads the latest answer of each agent ($(...).first() is the latest
  run), places the meetings by code after the lead, runs that agent's checks, and sets `route`: the same agent once more
  with `previous_output` and `violations` (first pass only, from `$prevNode.runIndex`), the next agent, or `done` with
  the compiled plan (same v2 plan format, plus `sizing`; every check still unmet is listed in `violations` and reaches
  the run log through Assemble drafts). An agent that fails twice ends the chain with no plan, as v2 did.
- **Route** (Switch, expression mode): 0 Phase Architect, 1 Workstream agent, 2 Deliverable agent, 3 Governance
  agent, 4 Assemble drafts.
- The Phase Architect has no output parser: its schema sits at the end of its system message and Chain check parses its
  text (strips a code fence, unwraps `{"output": ...}`, parses a JSON string inside it). Live runs 830, 831 and 872
  (Oct 21): the lead's answer came back as `{"output": "<JSON as a string>"}`; the parser rejected it, and in 872 its
  fixer returned nothing, so the chain stopped with no plan. Broken JSON now becomes a `format:` violation and the lead
  retries once with it. The other three agents keep their parsers, which auto-fix the format with their own fixer
  model (`Model: ... fixer`, same fix-format-only prompt as the research parsers).
- Context Writer: output cap 2,000 -> 8,000. Run 831 spent all 2,000 tokens thinking and returned nothing, so the
  situation slide was dropped.

Tests: `node n8n/tests/chain_test.js` replays saved answers through chain_check.js with n8n-like lookups (25 checks, including the lead's text-answer forms);
`node n8n/tests/make_pins.js chain|chain_error` builds the in-n8n wiring test (execution 826 ran the whole loop).
In a pinned run the pinned agents answer any run index, so the pass comes from `$prevNode.runIndex` (probe, execution 827).
Not in this build: the Plan Reviewer (fifth agent); its role is still José's decision. The run logger lists the new
agents' model calls in Run log totals but not yet as their own Agent log rows (its AGENTS list predates them).

## Run logger (workflow "JML run logger", id mqEGPCkfgZ8anFwQ)

Every morning at 07:17 Lisbon it copies each finished run of the proposal workflow (executions from 762 on)
into the **Run log** and **Agent log** tabs of `JML_Financial_Model`, writing data columns only
(Run log A–M and S–X, Agent log A–J and L); the sheet's formula columns price the rows.
Source: `workflows/run_logger.sdk.js`; parsing logic: `code/log_runs.js` (testable with node against saved executions).

- **Purpose** (Run log X): `Live` only for email briefs whose sender domain is on Inputs `Firm_Domains` (B68:B77);
  any other outside sender is `Measurement` with Sample `Unlisted sender`; `Debug` for manual runs, untagged
  webhook runs and emails from jml-ops.com / example.com; `Measurement` with Sample = tag for webhook runs with
  `log_purpose: "Measurement"`, `log_sample`, `log_round` in the body, or emails tagged `[B0]`, `[T1]` … `[T99]`
  (optional suffix, e.g. `[T2-PDF]`). An email subject with `[DEBUG]` is always Debug.
- **Confidentiality**: for Live and unlisted-sender runs, Run log C holds the Gmail thread ID, never the subject,
  and error text is left out of the notes.
- **No double logging**: executions already in Run log column A are skipped and counted (`skippedAlreadyLogged`).
- A questions-only reply is never a failure: deck failures are detected only on the deck-failure branch
  (`Reply without deck`, `Flag deck failure`), which the questions route never reaches.
- **Category** (Run log D): `Live run`, `Live questions`, `Test round N` or `Debug` — never "Full build (current pipeline)".
- **Page-read credits** come from `credits_used`, which the read-page tool returns since 17 Oct (version 1f0d1def).
- **Phase Architect tokens** under streaming are rebuilt as 11,553 input per call and model time × 156.2 output tokens/s.
- Needs two credentials: an **n8n API** key (Settings → n8n API) and **Google Sheets OAuth2** for the sheet owner.
