# JML AI Analyst — deck render service (v1)

A tiny web service that turns the AI Analyst's JSON into a 6-slide `.pptx`
(Title · Agenda · Context · Market Research · Next Steps · Conclusion).
Native PowerPoint shapes — no think-cell, no template file. This is the v1
"get the loop working" renderer; the richer template comes later.

```
deckgen.py   the slide builder (build_deck(data) -> pptx bytes)
app.py       Flask service: POST /render , GET /health
Dockerfile   for Cloud Run / any container host
Procfile     for Render / Railway / Heroku-style hosts
requirements.txt
```

## 1. Deploy it (pick one)

Every option needs one env var: **`JML_API_KEY`** — any long random string.
n8n will send it back in a header, so the endpoint isn't open to the world.

**A. Render.com (easiest, free tier)**
1. Put these files in a GitHub repo.
2. Render → New → Web Service → point at the repo.
3. Runtime: Docker (it finds the Dockerfile) — or Python with start command
   `gunicorn app:app`.
4. Add env var `JML_API_KEY = <your-secret>`. Deploy.
5. Your URL is `https://<name>.onrender.com`. Test: open `…/health`.
   (Free tier sleeps when idle; the first request after a nap takes ~30s.)

**B. Google Cloud Run**
```
gcloud run deploy jml-deck --source . --region europe-west1 \
  --allow-unauthenticated --set-env-vars JML_API_KEY=<your-secret>
```
Gives an `https://…run.app` URL. Scales to zero; no idle cost.

**C. Local + tunnel (fastest for a first test, nothing hosted)**
```
pip install -r requirements.txt
JML_API_KEY=<your-secret> python app.py          # listens on :8080
# in another terminal, expose it:
cloudflared tunnel --url http://localhost:8080   # or: ngrok http 8080
```
Use the public tunnel URL in n8n. Your machine must stay on.

**Check it works:**
```
curl -X POST https://<your-url>/render \
  -H 'X-API-Key: <your-secret>' -H 'Content-Type: application/json' \
  --data @sample_payload.json -o test.pptx
```

## 2. The request contract

`POST /render`, header `X-API-Key: <secret>`, body = JSON below. Every field
is optional; a missing one falls back to a placeholder, so a thin brief still
renders six slides. Returns the `.pptx` as the raw response body.

```json
{
  "meta":   { "kicker": "CONSULTING PROPOSAL", "subject": "…", "date": "October 11, 2026",
              "footer": "JML Operations — draft generated by the AI Analyst",
              "filename": "proposal_draft.pptx" },
  "cover":  { "title": "…", "subtitle": "…" },
  "agenda": { "title": "Topics for today's discussion",
              "items": ["Context", "Market Research", "Next Steps"] },
  "context":{ "title": "…", "bullets": ["…", "…"] },
  "market_research": {
      "title": "…",
      "rows":  [ { "actor": "…", "finding": "…", "implication": "…" } ],
      "sources": ["https://…", "https://…"] },
  "next_steps": { "title": "Proposed next steps", "bullets": ["…", "…"] },
  "closing":    { "title": "Thank you", "subtitle": "…" }
}
```

`market_research.rows` is where the two researchers' findings go: `actor` =
who, `finding` = what is happening, `implication` = why it matters. 1–4 rows
render cleanly; more will overflow the slide.

## 3. Wiring it in n8n (once the URL is live)

**HTTP Request node** (between the content-assembly node and the Gmail reply):
- Method: `POST`
- URL: `https://<your-url>/render`
- Headers: `X-API-Key` = your secret
- Body: JSON → the deck object (built by the assembly node from the brief,
  the profiler and the researchers)
- Options → Response → **Response Format: File**, put output in binary
  property `data`

**Gmail reply node:** attach binary property `data`, filename e.g.
`proposal_draft.pptx`.

## Work-plan slides and plan size

`workplan.py` scales with the plan: the week axis labels about 16 ticks at most
(every week up to 16 weeks, then every 2, 4, 8...), timeline rows shrink to 0.3"
and then continue on a second page (whole phases kept together), the
deliverables table pages at 13 lines with balanced pages, and steering meetings
page at 4 per slide. `python3 tests/workplan_stress.py [outdir]` checks 36
synthetic plans (4-52 weeks, 3-12 workstreams) for text overflow, overlaps and
shapes off the slide. Live check on the Navigator brief at 6, 12, 24 and 40
weeks: executions 403, 50, 404 and 555.
